### 6.3 Sampling uncertainty and stated limits

- **One run per arm.** Label the result one-run; a headline claim needs
  independent runs (`docs/methodology-standard.md` §5.5).
- **n = 50.** The suite is "a screening instrument, not a population sample;
  category-level splits (17/17/16) are the granularity the sample supports"
  (`docs/methodology-standard.md` §6). No subgroup smaller than a category may
  carry a claim.
- **Suite limits** (must be repeated verbatim in spirit): single-file Python
  tasks only; one baseline vendor (`deepseek-v4-pro`); n = 50
  (`docs/methodology-standard.md` §6).
- **Instability context:** across four committed full runs at temp 0.2, 19/50
  tasks flipped at least once (`docs/parity-report-phase1.md` Addendum 4 item 5).
- **Failure to reject is not equivalence.** If the McNemar p-value is not
  significant, or the time CI includes 0, the honest statement is "the
  difference was not resolved at n = 50", never "the arms are equivalent"
  (`docs/symmetric-baseline.md` power caveat).
- Any paired test whose discordant count is 0 is reported as p = 1.0 with the
  discordant count shown (as in `docs/symmetric-baseline.md` pair (a)).
