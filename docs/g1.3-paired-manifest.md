## 1. Question, bar and failure semantics

### 1.1 Question

Does the local SwapOS pipeline — reason → code → sacred grader → critic →
retry, specialists swapped per phase, cross-turn KV prefix cache on the CODE
retry — complete the frozen 50-task suite at a **mean total time per task
≤ 2× the frontier API mean**, while **G1.2 quality is maintained**?

The two arms are measured on the identical frozen task set under an identical
loop protocol (§2).

### 1.2 Bar (pre-registered; not weakened)

| Item | Value | Source |
| --- | --- | --- |
| Frontier API reference mean | **19.26 s/task** (`mean_latency_s`) | `benchmarks/results/baseline-deepseek-v4-pro-20260807-001937.json` |
| Reference run | 48/50 = 96.0 %, suite `swapos-v1`, model `deepseek-v4-pro`, run_at `2026-08-06T22:19:37Z`, wall 1058.0 s | same JSON (`tasks_passed`, `pass_rate`, `wall_clock_s`) |
| Repository's stated bar | "mean wall-clock per task ≤ **38.6 s** (= 2× the 19.3 s API mean)" | `docs/phase1-pipeline-RUN.md` §"Run 4 — G1.3 native-arch (deciding instrument)"; `docs/parity-report-phase1.md` §Verdict table (`≤ 38.6 s (2×)`) |
| **Pre-registered threshold used here** | **≤ 38.52 s** mean pipeline total time per task = 2 × 19.26 s (unrounded committed mean) | arithmetic on the committed `mean_latency_s`; stricter than the repo's rounded 38.6 s statement |
| Bar metric | pipeline arm: mean of per-task `wall_clock_s` over the 50 tasks (= JSON `mean_wall_clock_s`); reference: the committed single-shot API mean above | `pipeline/run_pipeline.py` `build_summary()` (`mean_wall_clock_s`) |

**The bar is not weakened.** This manifest adopts the *unrounded* committed
reference (2 × 19.26 s = 38.52 s), which is stricter than the repository's own
rounded statement (38.6 s). No threshold in this document may be changed after
the run; a threshold change invalidates the pair (§5).

**Committed near-miss context (historical, not this experiment):** the
sequential full-50 run measured 41.99 s/task (2.18×) and the overlap engine
40.83 s/task (2.12×) — `benchmarks/results/sequential-colab-27b-20260820-full50-8192.json`,
`benchmarks/results/overlap-colab-27b-20260820-full50-8192.json`,
`docs/parity-report-phase1.md` Addendum 3, `STATE.md` §"Broken / incomplete".
Those are the numbers the paired run must beat; they are references, not
results of this experiment.

### 1.3 Failure semantics

1. **Missing the bar is data, never hidden.** If the measured mean exceeds
   38.52 s, the report states it, the run stays in `benchmarks/results/`, and
   **G1.3 remains open** (AGENTS.md §2.8; `docs/methodology-standard.md` §5.4).
2. **Failure to reject a difference is not equivalence.** A paired test that
   does not reach significance does not prove the arms are equal
   (`docs/symmetric-baseline.md` §"Paired statistics", power caveat:
   "p > 0.05 does not prove equality, it means the observed gap is inside
   noise").
3. **A subphase improvement does not close G1.3.** The KV prefix cache is
   measured at −91.8 % retry-phase prefill
   (`benchmarks/results/kv-cache-local-4b-20260824-083718.json`) but retry
   prefill was only 0.51 % of the 27B full-suite wall time, so the committed
   projection is ~2.11× — G1.3 stays open unless whole-task time actually
   crosses the bar (`docs/g1.3-kv-prefix-cache.md` §"G1.3 projection at 27B
   scale"; `STATE.md` §"Broken / incomplete"). Subphase results are reported
   separately (§ report scaffold).
4. **Quality regression blocks closure.** Crossing the time bar while G1.2
   falls below its bar (≥ 76.8 % = 80 % of the 96.0 % baseline; `STATE.md`
   §"Frontier baseline") does not close G1.3.
5. **An invalid experiment is labeled invalid, kept, and re-run**
   (`docs/execution/TECHNICAL_SPEC.md` §"Compatibility and rollback";
   `docs/execution/WORK_PACKETS.md` SWAP-03 failure/rollback).

## 2. Treatment contrast — the only value that varies

### 2.1 The immutable run pair

One **immutable run pair**: two runs over the same frozen 50-task suite, in
the same order, under the same loop protocol, differing in exactly one
declared treatment.

| | Arm L (local) | Arm F (frontier API) |
| --- | --- | --- |
| Engine | SwapOS pipeline, local specialists swapped per phase | `deepseek-v4-pro` over `https://api.deepseek.com` |
| Runner | `pipeline/run_pipeline.py` | `benchmarks/harness/run_symmetric_baseline.py` (§3.6) |
| Loop | REASON → CODE → sacred grader → CRITIC (600-char bound) → retry, ≤ 3 attempts | the same loop, same prompts, same bound, ≤ 3 attempts |
| Evidence | new JSON in `benchmarks/results/` | new JSON in `benchmarks/results/` |

### 2.2 The single declared treatment contrast

**Treatment = the inference engine of the arm (local specialist pipeline vs
frontier API), everything else held fixed.**

Every other value in §3 — task pack and order, loop shape, prompts, feedback
bound, retry budget, temperature, context size, grader, warm/cold policy, run
procedure, evidence rules — is identical for both arms or is a per-arm
property that is fixed in advance by this manifest (§2.3). In particular, the
local arm runs the pre-registered CODE-retry KV prefix cache configuration
(§3.4); that is a fixed property of arm L, not a second variable, and it may
not be toggled between the two arms or mid-run.

### 2.3 Known per-arm protocol properties that are NOT free variables

These are pinned, documented asymmetries; they are part of the arms by
construction and must not be "corrected" after results are seen:

| Property | Arm L | Arm F | Committed justification |
| --- | --- | --- | --- |
| Output budget | `--max-tokens 2048` | `--max-tokens 8192` (counts `reasoning_content`) | `benchmarks/harness/run_symmetric_baseline.py` docstring: "max_tokens 8192 (the baseline's setting — deepseek-v4-pro counts reasoning_content toward the budget, unlike the pipeline's enable_thinking=False 2048-token budget)" |
| Thinking tokens | `"enable_thinking": false` | model-native reasoning | `runtime/llama_backend.py` `generate()` body |
| Number of models | 2 specialists (27B reason+code, 8B review) | 1 model (all phases) | committed run JSONs `models`, `benchmarks/run_symmetric_baseline.py` docstring ("SAME model for the CODE and critic phases") |
| Cost basis | local inference, zero marginal API cost, zero egress | metered API tokens, `cost_estimate_usd` + `price_notes` | `docs/methodology-standard.md` §4; `benchmarks/results/*.json` |

The bar metric (§1.2) compares pipeline per-task wall time (includes grader
and swap overhead) against the committed API call latency (excludes grading).
That asymmetry predates this manifest, is part of the committed bar
definition, and is **stricter for the pipeline**; it is preserved unchanged.

`--backend` is omitted deliberately: the default is `llama`
(swap-per-phase, sequential), which is the pinned arm L configuration (§3.3

Arm F — frontier API through the identical loop:

The API key is read from the environment and is never written into a result

## 5. Invalidity rules (pre-registered)

The pair is **invalid** — reported as invalid, retained, and re-run under a
new ID — if any of the following holds:

1. **Suite or grader revision changed** between the pinned digest (§3.1.1) and
   the run, or the run-time digest re-check (R8) differs.
   Source: `docs/methodology-standard.md` §2 ("Any change to the suite (tasks)
   or to the grader **invalidates the comparison**").
2. **Any pinned value in §3 deviates** from the executed run (models or
   quantization, context, temperature, output budget, retry budget, feedback
   bound, handoff mode, backend, cache policy, runner identity, prompts,
   warm/cold policy). A deviation must be declared before the arm runs and
   re-registered; it cannot be absorbed after seeing results.
3. **The suite is partial** (`tasks_total != 50`, arm-F `partial: true`, a
   runner abort, cost-cap stop, or host failure): the run may be reported as
   partial evidence but cannot carry a G1.3 verdict.
4. **The raw JSON is not committed byte-identical** (E2 sha256 mismatch), or
   a result was edited/reconstructed after the fact.
5. **A known infrastructure/code-defect class corrupted tasks.** The
   historical classes are recorded in `docs/phase1-closeout.md` §4 (Drive-cache
   exec bit, llama.cpp DeltaNet CUDA bug #27164, CUDA arch lock, truncated
   GGUF, stale sessions) and `docs/parity-report-phase1.md` Addendum 4 item 2
   (NameError on server-start failure corrupted 5/10 + 8/11 + 11/15 failures
   across three runs, forcing a downgrade of their conclusions). Affected tasks
   are recorded distinctly as infrastructure failures, never as model failures,
   and the arm is re-run if the class is systematic.
6. **Cross-run cache reuse occurred** (a KV namespace not fresh for the arm,
   §3.4 C1/C3), or a restore silently produced wrong output — cache identity
   reuse across runs is not yet safe by design (ADR-0006 §"Non-decisions").
7. **The bar or its denominator is changed, recomputed, or re-based after the
   run** (e.g. switching the denominator from the committed 19.26 s to a
   newly-measured API mean), or tasks are cherry-picked/excluded
   (`docs/execution/WORK_PACKETS.md` SWAP-03 non-goals).
8. **Quality evidence is missing**: no absolute pass counts and denominators
   per arm, or a failure excluded from the denominator.
9. **The two arms are not the same frozen task set in the same order**, or an
   arm's tasks were re-run selectively after the other arm's results were seen.

An invalid run does not close G1.3 and does not weaken the bar
(`docs/execution/WORK_PACKETS.md` SWAP-03 failure/rollback).
