# G2.4 — Capsule v1 integration note (issue #15 closure)

Status: **ready for reviewer approval; closes issue #15 when approved.**

## What exists

- The **Capsule v1 compression stage** is implemented in
  `capsule/compress.py`: a deterministic, pure-function `compress()` that
  rolls up decisions per phase, reduces old artifacts to path + summary,
  keeps the newest artifact and the verbatim core (goal/constraints) intact,
  and enforces a fixed token budget — **default 8k** (`DEFAULT_BUDGET_TOKENS`,
  section-share budget in `SECTION_SHARES`). A pluggable `summarizer` hook
  allows a model-based roll-up later; the deterministic path is correct alone.
- It is **unit-tested** in `capsule/tests/test_compress.py`: budget
  respected, verbatim core preserved, compressed capsule still round-trips
  through `Capsule.from_json` + `validate()`, **sub-linear growth** (n=4→16
  iterations grows < 2× where linear would be ~4×, capped at 8k),
  deterministic output, `growth_ratio` metric. (G2.4 tests are part of the
  repo gate.)

## What the running loop does — and must keep doing

- The Phase-2 operating point does **NOT** wire compression into the loop
  (`pipeline/loop.py` imports `capsule.capsule`, never `capsule.compress`).
  Context stays bounded by the **600-char critic-feedback cap**
  (`feedback[:600]` in the CODE prompt and the capsule decision) + the
  **8192-token context window** + **max-iterations 3**.
- The record rides on that exact path: **47/50 = 94.0%** sequential at
  8192 ctx (`benchmarks/results/sequential-colab-27b-20260820-full50-8192.json`),
  97.9% of the frontier baseline. **Compression must NOT be retrofitted into
  the running path** — any change to the handoff that produced the record
  invalidates it. The bounded-feedback change is what unlocked the retry loop
  (docs/parity-report-phase1.md addendum 3).

## When compression is the mechanism

- Compression is the **designated mechanism for long-horizon / overflow
  runs**: when a task's capsule would exceed the budget (deep retry chains,
  multi-file artifacts, future long-horizon tasks), `compress()` keeps the
  capsule under budget with sub-linear growth. Decision point: a future
  task-config knob (e.g. `capsule_budget_tokens`) or an explicit overflow
  path, decided under ADR discipline — not a silent change to the current
  operating point.
